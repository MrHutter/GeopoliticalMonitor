# v0.1 Product Specification

Geopolitical Monitor v0.1 is a Windows desktop application.

It is intended to become a desktop-first geopolitical situational-awareness workstation for OSINT and geopolitical research.

Planned v0.1 capabilities:

- Native Windows desktop shell.
- Embedded React application interface.
- World geopolitical map.
- Normalized geopolitical events.
- Event feed.
- Locally persisted user-created Watchlists with explicit Event membership.
- Watchlist-level monitoring for material updates to existing watched GDACS Events, with persistent unread/read in-app Alert history.
- Selected-event details.
- Source and timeline presentation.
- GDACS earthquake refresh on an in-app 30-minute timer while the app is open, plus a manual refresh action, with point epicenters, DatasetRecord provenance, and a provider status strip.
- UCDP Candidate conflict Events from monthly CSV releases (no credentials), checked every 6 hours on the in-app timer while the app is open plus a manual `Refresh UCDP` action; data is up to about 50 days old, shown as Unverified with the UCDP citation, and never creates Alerts.
- Explicit ReliefWeb report discovery and metadata-only SourceItem attachment for a selected Event.
- Explicit transient NASA FIRMS NOAA-20/NOAA-21 fire and thermal-anomaly viewport layer.
- No-cost, user-operated X website pane with reversible left/right placement.
- Orange default accent.
- Blue, red, green, and yellow alternate accents.

The active X direction is a normal X website pane, not an API-backed feed. The user manually signs into and operates X in an isolated WebView2 browser surface. This provides access to the user's normal X website experience without X Developer access, paid API credits, OAuth app configuration, API keys, scraping, DOM extraction, or automated interaction. Users may explicitly copy the canonical public URL of the currently open X status page, then manually paste it into the selected Event's Sources view. Submission creates or reuses a persistent URL-only XPost association and locally derives only its publication timestamp from the public numeric status ID.

The foundation now includes the desktop dashboard shell, local MapLibre basemap, SQLite-backed accent/X-pane preferences, SQLite-backed fictional demo Event/SourceItem data, locally persisted Watchlists, Watchlist-level GDACS monitoring with persistent in-app Alert history, GDACS earthquake ingestion on an in-app timer while the app is open plus a manual action, explicit ReliefWeb report discovery/attachment, a transient manual NASA FIRMS viewport layer, and the isolated X website pane. A Watchlist is a user-named collection of explicit existing Event memberships; deleting one preserves Events and Sources while removing its Alert rule and history. The map remains between X and Events: `Events | Map | X` when X is right, and `X | Map | Events` when X is left.

It does not implement live X API integration, X timeline ingestion, automatic X post import, post-content extraction, automatic refresh of providers other than GDACS and UCDP Candidate, provider refresh while the app is closed, non-earthquake GDACS hazards, automatic ReliefWeb matching/Event creation/body storage, cross-provider correlation, AI, actors, dynamic Watchlist criteria, automatic matching, new-Event/source-attachment Alerts, Windows notifications, app-closed monitoring, cloud/accounts, or installer packaging. ReliefWeb live access remains unconfigured until an approved native `appname` is supplied.

FIRMS observations are independent transient map data, not Events or evidence. Each explicit refresh atomically combines NOAA-20 and NOAA-21 VIIRS NRT detections fetched across two provider calendar days and filtered to the bounded viewport's rolling latest 24 hours. Visibility is off by default and session-only. The default Significant display preset shows nominal/high-confidence observations with FRP >= 10 MW; Strong only uses FRP >= 50 MW; All detections exposes the complete valid snapshot. These are application display presets, not NASA severity categories, and switching them performs no provider request. FIRMS does not fetch at startup or on navigation, persist observations, create or update Events/Sources, participate in Watchlists/Alerts, infer wildfires/perimeters, cluster points, or expose product/time controls.

The bundled neutral sovereign basemap follows internationally recognized borders and represents Crimea within Ukraine. Sovereign reference geography is distinct from any future sourced and timestamped operational-control or occupation overlay.

The Event panel starts each launch at the non-persisted `All Events` scope. Selecting a Watchlist scopes the shared Event-row and Map-marker collection; search, time range, and minimum severity apply with AND semantics. Filtering runs natively, and the list and map show at most the newest 2,000 matching Events by last update, with a notice and the total count when more match; `ALL` remains the startup default and means no time limit. Rows are listed newest first by last update and scroll inside the bounded Events panel; older Events are reached by scrolling. Watchlist activity never triggers provider behavior.

The desktop layout is width-protected: X is auxiliary, the main application keeps a 940 px minimum, Events stays bounded at 300-320 px (up to 340 px on very wide app views), and the Map takes the remaining workspace width. Events and Map do not vertically stack in supported desktop layouts. The top bar stays on one row from the 940 px minimum up and keeps brand, Local Desktop status, search, all time ranges, UTC, a labelled Alerts control and Settings reachable. The former info bar is not shown on the main screen; its facts are in Settings. Settings owns the five accent choices and exposes read-only application/runtime information already supplied by the typed native bridge.

GDACS earthquake Events use `NaturalDisaster` and `Unverified`, where `Unverified` means not independently verified by Geopolitical Monitor. Alert level and magnitude remain GDACS-labelled source metadata and never determine Event status. Refresh is user-triggered, four-day bounded, idempotent, and non-destructive when records disappear or the provider fails.

Alert monitoring has one fixed rule per Watchlist: notify in the in-app history when a strictly newer GDACS revision materially changes an already watched Event's title, summary, start time, or stored location. Enabling does not backfill. New Events, revision-only or source-only changes, repeat/stale/conflicting provider data, manual attachments, and membership edits remain silent. Alert history supports unread/read only, is loaded on demand, and remains local. GDACS refreshes automatically only while the app is open; nothing runs while the app is closed.

`Geopolitical Monitor` is still the provisional visible product name. Its frontend and native display uses are centralized within their respective runtime boundaries. Stable internal identities deliberately retain `GeopoliticalMonitor` or `geopolitical-monitor`, including LocalAppData paths, database and WebView2 profile names, namespaces, project/assembly/package identities, preference keys, and `app.geopoliticalmonitor.local`. A future branding decision is not authority for an internal identity or persistence migration.

X remains a user-operated website pane. Copy Post Link and context-menu Copy X Post Link copy only normalized public status URLs when WebView2 naturally exposes such a URL; copying alone does not import SourceItems or extract post content. Explicit attachment occurs only after the user pastes and submits that URL in the privileged application UI. The app must not inject into X to alter content or scrollbars.

The isolated X pane uses native WebView2 capabilities for a responsive toolbar with overflow. Production AdBlock installation is user-invoked and accepts only a payload matching the compiled reviewed Chrome Web Store AdBlock `6.47.0` authority. The app authenticates the complete runtime tree except `_metadata/**`, performs bounded streaming staging, and verifies staging and final LocalAppData `Current` before installing. Startup recovers interrupted activation and revalidates saved schema-2 authority and managed payload before enabling extensions; old or mutated state requires explicit re-enrollment. Reconciliation never binds an arbitrary same-ID runtime: it removes that unbound instance, performs a fresh verified add, and only then persists authority. Enable, disable, refresh, reconciliation, and removal target only the exact trusted binding and runtime instance. The official Store ID/version/digest establish payload provenance, while the managed WebView2 runtime ID establishes only installed-instance identity. A separate user-invoked diagnostic remains available for capability support but cannot establish trust. Geopolitical Monitor does not download, bundle, redistribute, silently install, or automatically update a blocker. FluentOverlay remains deferred.
